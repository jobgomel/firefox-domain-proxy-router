# Code Review: Domain Proxy Router (Firefox Extension)

## 1. Структура проекта

```
src/
  background/
    main.js        — входная точка
    proxyRoute.js  — маршрутизация прокси-запросов
    state.js       — глобальное состояние (isEnabled, domains, proxies, rules)
    ui.js          — бейджи вкладок, иконки, кеш URL
    utils.js       — matchRule, wildcardToRegex
  popup/
    popup.html
    popup.js       — попап-интерфейс
  options/
    options.html
    options.js     — панель управления (~870 строк, монолит)
  global.css
```

**В целом** проект хорошо структурирован, файлы разделены по назначению. Основная проблема — `options.js` (872 строки). Это единственный монолит, который стоит декомпозировать.

## 2. Работа с состоянием

**Проблемы:**
- В `options.js` состояние хранится в глобальных переменных (`appState`, `editingProxyId`, `editingDomainId`, `currentTab`), нет отдельного модуля состояния.
- Нет единой точки сохранения — `saveData()` вызывается в 5+ местах вручную. Легко забыть вызвать после мутации.
- `renderAll()` вызывается только внутри `saveData()`, что означает: если данные изменились без `saveData()` (например, при редактировании), список не обновится.

**Рекомендации:**
- Вынести состояние в отдельный модуль `state.js` с методами-мутаторами, которые автоматически вызывают `saveData()` и `renderAll()`.
- Использовать единый `appState` объект.

## 3. Дублирование кода

**Найдено несколько мест:**
1. **testProxyAndShowStatus** — функция тестирования прокси определена дважды (в `options.js` и `publicProxies.js`).
2. **i18n** — цикл `querySelectorAll('[data-i18n]')` повторяется в `popup.js` и `options.js`.
3. **buildProxyResponse** — формирование объекта ответа прокси повторяется 4 раза в `proxyRoute.js`.
4. **Авторизация** — обработка `onAuthRequired` логически изолирована, но находится в `main.js`.

**Рекомендации:**
- Вынести `testProxyAndShowStatus` в отдельный модуль `testProxy.js`.
- Вынести i18n в `shared/i18n.js`.
- Вынести `buildProxyResponse` в `utils.js`.
- Вынести `handleProxyAuth` в `auth.js`.

## 4. Чистота кода

**Проблемы:**
- В `options.js` перемешаны инициализация, рендеры, обработчики событий и утилиты. Нет четкой группировки.
- Длинные функции рендеринга (`renderProxies`, `renderDomains`), где inline создаются DOM-элементы — читаемость страдает.
- В `popup.js` функция `updateStatusText` завязана на ID из HTML, но сам HTML отсутствует в контексте чтения.

**Рекомендации:**
- Разделить `options.js` на модули по функциональным группам.
- Создать `helpers.js` с фабриками для типовых элементов (карточка, controls, badge).
- Группировать код в `options.js`: инициализация → рендеры → формы → экшены.

## 5. Обработка ошибок

**Проблемы:**
- Нет обработки ошибок при `fetch` публичных прокси, кроме HTTP status. Нет fallback при сетевой ошибке.
- `decodeURIComponent` вызывается без try/catch — может выбросить исключение на некорректной строке.

**Рекомендации:**
- Обернуть `decodeURIComponent` в try/catch.
- Добавить обработку сетевых ошибок при загрузке публичных прокси.
- Улучшить user-facing сообщения об ошибках.

## 6. Смешение слоёв (UI и логика)

**Проблема:** `proxyRoute.js` импортирует `addHostToTab`, `setTabIconProxied` из `ui.js`. Функция маршрутизации не должна знать про UI.

**Рекомендация:**
- Передавать колбэки через параметры из `main.js`, а не импортировать UI напрямую.

## 7. Тестируемость

**Проблемы:**
- Все функции работают с глобальным `appState`. Нет pure-функций, которые можно протестировать изолированно.
- `matchRule` использует регулярки из глобального кеша, что усложняет тесты.
- Невозможно протестировать `options.js` в node.js, т.к. он завязан на DOM и `browser.*` API.

**Рекомендации:**
- Вынести чистую логику (matchRule, wildcardToRegex) в отдельные тестируемые функции.
- Использовать dependency injection для `browser.*` API.

## 8. Комментарии и нейминг

**Проблемы:**
- Избыточные комментарии вида "ЛОГИКА ТЕМЫ", "ЛОГИКА ВКЛАДОК" — они не несут пользы, когда функция и так называется `switchTab`.
- В `ui.js` есть комментарий с вопросом: `// Проверь, есть ли у тебя функция setTabIconProxied ниже в этом же файле.` — явно забытый TODO.
- Названия переменных типа `d`, `p` в `options.js` — снижают читаемость.

**Рекомендации:**
- Убрать очевидные заголовки-секции, оставить только комментарии "почему".
- Убрать or исправить забытый TODO-комментарий.
- Переименовать однобуквенные переменные в цикловых контекстах вне цикла forEach.

## 9. Производительность

**Проблемы:**
- В `publicProxies.js` при загрузке 2000+ прокси строится DOM для всех отфильтрованных. Нет виртуализации или пагинации.
- `renderAll()` вызывается при каждом saveData — перерисовываются ВСЕ списки, даже если изменился один элемент.
- `innerHTML = ''` для очистки списков — можно использовать `replaceChildren()`.

**Рекомендации:**
- Ограничить отображаемые результаты 50-100 элементами.
- Использовать `replaceChildren()` вместо `innerHTML = ''`.

## 10. Безопасность

**Проблемы:**
- В коде нет `innerHTML` (кроме очистки), что хорошо. Но:
  - URL decode без try/catch (п.5)
  - Нет ограничения на количество загружаемых публичных прокси (может быть DoS)
  - Нет валидации типов при импорте JSON

**Рекомендации:**
- Обернуть decodeURIComponent в try/catch.
- Ограничить количество загружаемых публичных прокси.
- Использовать `replaceChildren()` вместо `innerHTML`.
- Валидировать структуру импортируемого JSON.

## Резюме

| Категория | Основные проблемы |
|---|---|
| Структура | options.js 872 строки, монолит |
| Дублирование | 4 места buildProxyResponse, 2 места testProxy, 2 места i18n |

| Обработка ошибок | Нет try/catch decodeURIComponent |
| Безопасность | Нет лимита публичных прокси |
| Тестируемость | Всё завязано на глобальное состояние |

2. Изолировать слои (п.6)
3. Разделить options.js (п.2, п.4)
4. Обработка ошибок и безопасность (п.5, п.10)
5. Производительность (п.9)
6. Комментарии и нейминг (п.8)
7. Тестируемость (п.7)
