# План рефакторинга: Производительность

## Проблемы

### 1. `renderAll()` при каждом save — полная перерисовка

`OptionsState` при каждой мутации вызывает `save()` → `renderFn()` → `renderAll()`,
которая перерисовывает ВСЕ 4 списка (proxy, domain, rule + selectors), даже если
изменился один элемент.

Текущий вызов:
```
addProxy(id, config) → save() → renderFn() → renderAll() → renderProxies + renderDomains + renderRules + updateRuleSelects
```

Лишнее: при добавлении прокси перерисовываются domains и rules, которые не менялись.

### 2. `innerHTML = ''` для очистки списков

Используется в 6 местах:
- `renderProxies` (строка 109)
- `renderDomains` (строка 141)
- `renderRules` (строка 169)
- `updateRuleSelects` (строки 214-215) — для select'ов `innerHTML` допустим
- `fetchPublicProxies` (строка 564)
- `renderPublicProxies` (строка 628)

`innerHTML = ''` заставляет браузер парсить пустую строку как HTML.
`replaceChildren()` быстрее и безопаснее.

### 3. Публичные прокси — уже ограничены 100 элементами

`renderPublicProxies` делает `slice(0, 100)` (строка 638). Для 100 элементов
виртуализация не нужна — DOM строится быстро.

## План

### Фаза 1: Селективный рендер

Добавить в `save()` параметр `renderHint`, а мутаторам — передавать его:

```js
// state.js
async save(renderHint = 'all') {
    await this._storage.set({ ...this._data });
    if (this._renderFn) {
        try { this._renderFn(renderHint); } catch (e) { ... }
    }
}

addProxy(id, config) {
    this._data.proxies[id] = config;
    return this.save('proxy');
}

deleteProxy(id) {
    delete this._data.proxies[id];
    this._data.rules = this._data.rules.filter(r => r.proxyId !== id);
    return this.save('proxy'); // rules изменились, но рендер rules не нужен — selectors обновятся
}

setExceptions(exceptions) {
    this._data.exceptions = exceptions;
    return this.save('exceptions'); // не требует рендера списков, только storage
}

replaceAll(data) {
    // ...
    return this.save('all');
}
```

В `options.js` `renderAll` становится диспетчером:

```js
function renderAll(section = 'all') {
    if (section === 'all' || section === 'proxy') renderProxies();
    if (section === 'all' || section === 'domain') renderDomains();
    if (section === 'all' || section === 'rule') renderRules();
    updateRuleSelects(); // всегда — быстро, и данные могли измениться
}
```

**Изменяемые файлы:**
- `src/options/state.js` — `save(renderHint)`, мутаторы передают hint
- `src/options/options.js` — `renderAll(section)` с диспетчеризацией

### Фаза 2: `replaceChildren()` вместо `innerHTML = ''`

Заменить во всех render-функциях:

```js
// Было:
list.innerHTML = '';
// Стало:
list.replaceChildren();
```

Кроме `updateRuleSelects` — для select'ов `innerHTML = ''` остаётся
(это стандартная практика для заполнения option).

**Изменяемые файлы:**
- `src/options/options.js` — 4 замены в render-функциях

### Фаза 3: Уменьшить public proxies с 100 до 50

Строка 638:
```js
// Было:
const limited = filtered.slice(0, 100);
// Стало:
const limited = filtered.slice(0, 50);
```

**Изменяемые файлы:**
- `src/options/options.js` — изменить лимит
