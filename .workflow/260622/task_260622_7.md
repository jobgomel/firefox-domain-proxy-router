# План рефакторинга: Тестируемость

## Проблемы

### 1. `utils.js` — `wildcardToRegex` не экспортирован, `regexCache` глобален

```js
const regexCache = new Map();   // module-level — не очищается между тестами

function wildcardToRegex(str) { /* ... */ }  // не экспортирована — нельзя протестировать

export function matchRule(urlObj, mask) { /* ... */ }  // использует wildcardToRegex
```

При тестировании `matchRule`:
- Кеш растёт от теста к тесту — возможны ложно-зелёные на совпадающих строках
- `wildcardToRegex` нельзя проверить изолированно

### 2. `proxyRoute.js` — `state` импортируется глобально

`handleProxyRequest` и `isUrlMatchRules` используют `import { state } from './state.js'`.
Для тестирования нужно подменять глобальный `state`, что чревато
перекрёстным влиянием тестов.

```js
import { state } from './state.js';  // жёсткая привязка

export function handleProxyRequest(details, { getTabUrl, onProxyMatch } = {}) {
    if (!state.isEnabled) { ... }  // глобальный state
    // ...
}
```

### 3. `OptionsState` — читает `browser.*` напрямую (частично)

`OptionsState` (src/options/state.js) вызывает `browser.storage.local.get/set`
напрямую (строки 36, 52). При тестах в Node.js `browser` не определён.

## План

### Фаза 1: Улучшить `utils.js`

- Экспортировать `wildcardToRegex`
- Добавить `resetRegexCache()` для очистки между тестами

```js
export function wildcardToRegex(str) { /* ... */ }
export function resetRegexCache() { regexCache.clear(); }
```

**Изменяемые файлы:**
- `src/background/utils.js`

**Что даёт:**
- Можно тестировать `wildcardToRegex` отдельно:
  `wildcardToRegex('*.example.com') → /^.*\.example\.com$/`
- Можно сбрасывать кеш между тестами: `resetRegexCache()`

### Фаза 2: Передать `state` в `handleProxyRequest` параметром

Вместо глобального импорта передавать `state` как аргумент:

```js
// Было:
import { state } from './state.js';
export function handleProxyRequest(details, { getTabUrl, onProxyMatch } = {}) {
    if (!state.isEnabled) { ... }

// Стало:
export function createHandleProxyRequest(state) {
    return function handleProxyRequest(details, { getTabUrl, onProxyMatch } = {}) {
        if (!state.isEnabled) { ... }
    };
}
```

Или проще — передавать `state` как третий аргумент:

```js
export function handleProxyRequest(details, { getTabUrl, onProxyMatch } = {}, state) {
    if (!state.isEnabled) { ... }
```

Второй вариант проще, не требует переименования.

**Изменяемые файлы:**
- `src/background/proxyRoute.js` — добавить параметр `state`
- `src/background/main.js` — передать `state` при вызове

### Фаза 3: Внедрить `browser` в `OptionsState`

Передавать `browser` как зависимость в конструктор:

```js
export class OptionsState {
    constructor(renderFn, storage = browser.storage.local) {
        this._storage = storage;
        // ...
    }

    async load() {
        const res = await this._storage.get(STORAGE_KEYS);
        // ...
    }

    async save() {
        await this._storage.set({ ...this._data });
        // ...
    }
}
```

**Изменяемые файлы:**
- `src/options/state.js` — добавить параметр `storage`
- `src/options/options.js` — `new OptionsState(renderAll)` → без изменений
  (дефолтное значение `browser.storage.local` подходит)
